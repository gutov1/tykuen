# Настройка Supabase для Тыкуэн

## 1. Создай проект

Создай проект в Supabase и открой Project Settings → API. Скопируй Project URL и publishable key (или legacy anon key).

В корне проекта создай файл `.env.local` на основе `.env.example`:

```text
VITE_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR_SUPABASE_PUBLISHABLE_OR_ANON_KEY
```

После изменения переменных перезапусти Vite. Файл `.env.local` не следует коммитить. Не используй service role key в браузере.

## 2. Настрой регистрацию

В Supabase открой Authentication → Providers → Email. Для соответствия требованиям проекта отключи подтверждение email. Тогда пользователь сможет зарегистрироваться и войти сразу после создания аккаунта.

В Authentication → URL Configuration укажи адрес локальной разработки `http://localhost:5173` в Site URL или Redirect URLs. Для опубликованного сайта добавь его домен отдельно.

## 3. Создай таблицу профилей

Открой SQL Editor и выполни содержимое файла `supabase/migrations/202610120001_profiles.sql`.

Миграция создаёт таблицу `public.profiles`, политики Row Level Security и триггер, который добавляет профиль после регистрации пользователя. Имя и населённый пункт также сохраняются в метаданных пользователя Supabase Auth.

## 4. Проверь работу

1. Запусти `npm run dev`.
2. Нажми «Войти» и открой вкладку «Регистрация».
3. Введи имя, населённый пункт, email и пароль длиной не менее 6 символов.
4. После регистрации проверь, что пользователь появился в Authentication → Users и его профиль есть в Table Editor → profiles.
5. Выйди и снова войди с теми же данными. После обновления страницы сессия должна сохраняться.

## Важные ограничения

- Для входа и регистрации используется Supabase Auth, а не локальная имитация.
- В браузере используется только publishable/anon key с включённым RLS.
- Публикация объявлений, сообщения, избранное и загрузка фотографий ещё не подключены к базе данных.
